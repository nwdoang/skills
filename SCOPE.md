# Repository Scope

A skill belongs here when it:

- solves a concrete problem;
- is reusable across projects;
- remains useful beyond one temporary situation;
- contains no confidential information; and
- can be explained independently of a private codebase.

Changes should ideally respond to observed behavior or an actual engineering need.

The following do not belong here:

- random prompt experiments;
- one-off project instructions;
- employer-specific processes;
- credentials or internal URLs;
- private project architecture; or
- speculative features with no demonstrated need.

Repeated rejected patterns may justify an explicit out-of-scope catalog later. One is not needed yet.
